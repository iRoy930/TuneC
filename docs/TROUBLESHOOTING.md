# 故障排查

本页收录已知问题与对应处理方式。每条按「症状 / 原因 / 解决」三段说明。

**排查任何问题前，先跑一次自检并保留输出：**

```bash
# 已安装（从 Releases 下载后拖进「应用程序」）：
/Applications/TuneC.app/Contents/MacOS/TuneC --selfcheck

# 从源码构建的，用构建产物：
build/TuneC.app/Contents/MacOS/TuneC --selfcheck
```

末行汇总形如 `✅31 ⏭️3 ❌0`。**❌ 数量不为 0 说明确实有失败项**；
⏭️ 是因为设备未接入或能力不支持而跳过（例如没接外接显示器时的 DDC 检查），属正常。

---

## 1. 调音量完全没反应

**症状**：滚动或用快捷键时 HUD 有变化，但音量实际不变；或连 HUD 都不出现。

**原因**：当前输出设备的音量后端选择失败。常见两类：

- 显示器不支持 DDC/CI 音量（很多显示器只实现了亮度 VCP `0x10`，未实现音量 VCP `0x62`），
  且没有启用虚拟音频环回，于是没有任何可写的音量通道。
- 输出设备本身不提供系统音量控制（无 `VolumeScalar`），例如部分 DP/HDMI 音频输出。

**解决**：

1. 跑自检，看第 10 项 DDC 结论与「当前输出设备的音量后端」这一行。
2. 若显示「DDC 音量不可用」，请在菜单中**启用虚拟音频环回**（「虚拟音频」组），
   用软件方式接管音量。
3. 使用虚拟音频环回时，若信号太小声，注意 BlackHole 后端会额外衰减信号，
   优先切换到 Tap 后端（见下一条）。
4. 若自检里「当前输出设备的音量后端」显示为「不支持」，说明该设备既无软件音量也不支持
   DDC 音量，同样需要启用虚拟音频环回。此时菜单里的「虚拟音频环回」开关会变灰，
   标题会变成「虚拟音频环回（未安装 BlackHole）」或「（系统不支持 Tap）」，
   下方提示行也会写明具体原因。

---

## 2. 菜单栏出现橙色麦克风指示点

**症状**：TuneC 运行时菜单栏持续显示橙色（或橙色圆点）麦克风使用指示。

**原因**：当前采用的是 **BlackHole 后端**。BlackHole 是虚拟输入设备，
读取它在系统看来等同于录音，会点亮麦克风指示点。

**解决**：把采集后端切到 **Tap（系统音频采集）**：

1. 若「虚拟音频环回」正在运行，先在菜单中**关闭**它（环回运行中不允许切换采集方式）。
2. 菜单 →「采集方式」→ 选择 Tap 后端，然后再重新启用「虚拟音频环回」。
3. 该后端需要 macOS 14.2+，并会申请「系统音频录制」权限；它**不占用麦克风**，
   切换后橙色指示点即消失。
4. 如果系统版本低于 14.2，则只能使用 BlackHole，橙色指示点无法避免
   （这是系统层面的提示，不是隐患）。

---

## 3. DDC 亮度 / 音量读不到

**症状**：自检第 10 项报「DDC 通道不可用」或「VCP 0x10 亮度读失败」；
菜单里亮度控制不可用。

**原因**：DDC/CI 未在外接显示器的 OSD 菜单中开启，或该显示器 / 连接方式
（如部分转接器、KVM、扩展坞的 HDMI 分支）不透传 DDC 通道。

**解决**：

1. 用显示器自带的 OSD 菜单进入设置，找到 **DDC/CI** 选项并**开启**
   （有些型号叫 DDC/CI、Display Data Channel，或藏在「其它设置」里）。
2. 优先使用 **Type-C / DP 直连**；经转接器、KVM 或某些扩展坞时 DDC 常被截断。
3. 更换线缆或换一个视频口重试，然后重新运行自检确认 VCP 读取是否恢复。
4. 若显示器固件确实未实现音量 VCP `0x62`，无需强求——改用虚拟音频环回即可。

## 4. 边缘滚轮手势不生效

**症状**：在屏幕边缘滚动滚轮，音量 / 亮度没有变化，也没有 HUD。

**原因**：两种可能——该功能**默认关闭**；或已开启但**辅助功能权限未授予**。

**解决**：

1. 菜单中确认「手势 → 边缘滚轮手势」开关处于**开启**状态。
2. 若「手势 → 设置」里显示「⚠️ 辅助功能未授权 — 点此授权」，点击该行会触发系统的
   辅助功能授权询问，按提示前往「系统设置 → 隐私与安全性 → 辅助功能」勾选 TuneC。
3. 授权后回到 TuneC 会**自动开启**手势，无需重启；若仍未生效，
   再执行第 1 步确认开关是否已打开。
4. 详见 [PERMISSIONS.md](PERMISSIONS.md) 中的权限重置与验证方法。

## 5. 开启虚拟环回后没有声音

**症状**：启用虚拟音频环回后，喇叭完全不出声。

**原因**：采集所需的权限未授予，导致音频通路建立失败并静默；或启用后
进程状态需要重启才能生效。

**解决**：

1. 确认对应权限已授予：Tap 后端需要「系统音频录制」，BlackHole 后端需要「麦克风」。
2. **退出 TuneC 并重新启动**，让权限与音频通路重新建立。
3. 在「系统设置 → 声音」中确认输出设备指向的是**你真正的扬声器或显示器**，
   而不是停在 BlackHole 上。
4. 仍无声时，关闭虚拟音频环回（回到系统音量直通），确认基础声音是否正常，
   以区分是环回链路问题还是系统输出问题。

## 6. 退出后系统声音没有了 / 卡在 BlackHole 上

**症状**：强制退出 TuneC 或异常终止后，系统声音消失，或声音继续走 BlackHole
却没有输出。

**原因**：BlackHole 后端在工作时会把**系统默认输出**切换到 BlackHole；
正常退出时 TuneC 会把它切回原设备。若进程被强制杀死，恢复流程可能来不及执行。

**解决**：

1. 手动把默认输出切回真实设备：「系统设置 → 声音 → 输出」中选中你的
   扬声器 / 显示器，或按住 `⌥` 点击菜单栏的音量图标切换。
2. 打开「音频 MIDI 设置」确认设备列表里 BlackHole 与物理设备都在。
3. 重新启动 TuneC，在菜单中**关闭虚拟音频环回**，让它按正常流程恢复并退出。
4. 建议今后退出时使用菜单里的「退出」，而不要强制结束进程。

## 7. 如何收集日志与自检输出（提交 issue 前必读）

提交问题前请附上以下两项，能大幅缩短定位时间。

**A. 自检输出**

```bash
build/TuneC.app/Contents/MacOS/TuneC --selfcheck
```

至少粘贴最后一行汇总（形如 `✅31 ⏭️3 ❌0`）；若有 ❌ 项，请连同该项上文的
上下文一起粘贴。

**B. 运行日志**

```bash
# 与问题发生时间点相关的片段即可，不必贴全文
tail -n 100 /tmp/tunec.log
grep -n -i -e error -e fail /tmp/tunec.log
```

`/tmp/tunec.log` 记录运行期的设备与路由事件，日志中的诊断信息可用于判断
后端选择与设备切换是否按预期发生。

提交 issue 请使用仓库的 [Bug 报告模板](../.github/ISSUE_TEMPLATE/bug_report.yml)，
其中要求填写 macOS 版本、芯片、TuneC 版本、外接显示器型号与连接方式。
