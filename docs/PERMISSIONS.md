# 权限说明

TuneC 在特定功能下会向系统申请权限。**除麦克风外，所有权限都不是安装即申请**，
只有当你真正用到对应功能时才会被要求；麦克风权限的触发时机见第 1 节。
本页逐条说明每个权限的用途、触发时机与撤销方式。

> 隐私承诺：**TuneC 不录音、不保存、不上传任何音频。**
> 采集到的音频只在内存中用于实时调节音量并转发到你所选的输出设备，
> 不写入磁盘，也不通过网络发送。

---

## 1. 麦克风（Microphone）

- **什么时候会被要求**：当采集后端选为 **BlackHole** 时，TuneC 会在**启动时**申请麦克风权限
  （即使当下未启用环回也会申请）。
- **为什么会需要**：BlackHole 是一个虚拟输入（录音）设备，读取它的数据在系统看来
  等同于从麦克风录制，因此必须走「麦克风」权限。缺少该权限时系统不会弹窗，
  而是直接拒绝，表现为采集到数字静音（自检中体现为 `capE=0`）。
- **如何撤销**：系统设置 →「隐私与安全性」→「麦克风」→ 关闭 TuneC。
- **提示**：使用 BlackHole 后端期间，菜单栏会出现**橙色麦克风指示点**；
  切换到 Tap 后端即可消除，参见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。

## 2. 系统音频录制（System Audio Capture）

- **什么时候会被要求**：在 macOS 14.2+ 上使用**系统音频采集（Tap）**后端时。
- **为什么会需要**：Tap 通过 Core Audio Process Tap 直接分接系统正在播放的声音，
  需要用户授权「录制系统音频」。这一层**不受麦克风权限管控**，因此
  **不会点亮橙色麦克风指示点**，也不占用麦克风。
- **如何撤销**：系统设置 →「隐私与安全性」→「屏幕与系统音频录制」中关闭 TuneC
  （不同系统版本中该面板名称略有差异）。
- **说明**：这是推荐的默认后端；若不支持（系统低于 14.2），应用会自动回退到 BlackHole。

## 3. 辅助功能（Accessibility）

- **什么时候会被要求**：启用「边缘滚轮手势」时（该功能默认关闭，首次开启会引导授权）。
- **为什么会需要**：在屏幕边缘用滚轮调节音量 / 亮度，需要拦截来自全系统的滚轮事件，
  这属于辅助功能权限的范围。授权前手势不会生效，其它功能不受影响。
- **如何撤销**：系统设置 →「隐私与安全性」→「辅助功能」→ 关闭 TuneC。

## 如何验证

### 方式一：重置后再触发，观察是否重新弹窗

TuneC 的 bundle identifier 为 `io.github.iRoy930.tunec`。可在终端重置单个权限
（重置后需重新启动 App 并再次使用对应功能）：

```bash
tccutil reset Microphone io.github.iRoy930.tunec       # 麦克风
tccutil reset AudioCapture io.github.iRoy930.tunec     # 系统音频录制
tccutil reset Accessibility io.github.iRoy930.tunec    # 辅助功能

# 一次性重置 TuneC 的全部权限
tccutil reset All io.github.iRoy930.tunec
```

若 `tccutil` 提示未知的服务名，说明你的系统版本对该类别使用了不同的服务标识，
此时直接到「隐私与安全性」面板中手动开关即可。

`tccutil` 还有三个前提，不满足时会「看起来成功、实际什么都没做」：

- **要在真实用户身份下执行**：麦克风与系统音频录制属于**用户级**授权。
  在 root 身份（或非交互环境）下执行只会作用于系统级库，用户库里的记录纹丝不动。
- **目标 App 必须可被系统解析**：该 bundle id 对应的 App 需要真实存在，且位于
  `~/Applications`、`/Applications` 等常规位置。已被删除或移走时会直接报
  `No such bundle identifier`。
- **删除是异步的**：命令打印 `Successfully reset` 只代表请求已受理，
  记录可能数秒到数分钟后才真正消失。立刻复查容易误判成「删不掉」。

### 方式二：用自检命令查看当前状态

```bash
build/TuneC.app/Contents/MacOS/TuneC --selfcheck
```

自检报告会列出当前环境的能力与状态（可作为判断权限是否生效的参考）。
菜单中的辅助功能入口也会直接显示「已授权 / 未授权」。

### 方式三：查看系统权限面板

「系统设置 → 隐私与安全性」中对应类别里，TuneC 前面的开关状态即为当前生效状态。
注意：**更换签名身份、或修改 App 的 bundle identifier，都会让已有记录失效**，
需要重新授权（原因见 [BUILD.md](BUILD.md) 的签名说明）。
其中改动 `CFBundleIdentifier` 还会在权限面板里多留下一条基于**旧 id 的孤儿记录** ——
它不影响新 id 的授权与功能，删除方法见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。
